# EntitlementKit

A reusable Swift package for web-billed product entitlements. It separates product plans, offline expiry resolution, installation identity, RevenueCat Web Billing, and lightweight SwiftUI components.

## Who it is for

Use this package when multiple Apple-platform applications need configurable paid plans and web checkout without duplicating entitlement logic. It supports macOS 13+ and iOS 16+.

The package does not contain your public API key, purchase-link URL, plan IDs, callback scheme, app branding, or business feature gates. Those stay in the consuming application.

## Package products

| Product | Purpose | External dependency |
| --- | --- | --- |
| `EntitlementKitCore` | Status model, offline expiry resolution, installation IDs, cache contract, URL builder | None |
| `EntitlementKitRevenueCat` | RevenueCat customer-info stream and redemption-link adapter | RevenueCat purchases-ios |
| `EntitlementKitSwiftUI` | Minimal configurable plan picker | SwiftUI |

## Installation

Add this repository in Xcode via **File → Add Package Dependencies**, then select the products your app needs. For SwiftPM:

```swift
.package(url: "https://github.com/prithvi-bommu/entitlement-kit-swift.git", from: "0.1.0")
```

## Quick start

```swift
import EntitlementKitCore
import EntitlementKitRevenueCat

let identity = UserDefaultsInstallationIdentity(
    key: "com.example.app.installation-id"
)
let gateway = RevenueCatEntitlementGateway(
    apiKey: "appl_your_public_key",
    entitlementID: "example_pro",
    lifetimePlanIDs: ["lifetime"],
    identity: identity,
    statusStore: UserDefaultsEntitlementStatusStore(key: "com.example.app.cached-entitlement")
)

await gateway.configure()

let web = WebBillingConfiguration(
    purchaseLink: URL(string: "https://pay.rev.cat/your-link")!,
    packageIDsByPlanID: ["monthly": "$rc_monthly", "yearly": "$rc_annual"],
    callbackScheme: "from-your-revenuecat-dashboard"
)
let checkoutURL = WebPurchaseLinkBuilder.makeURL(configuration: web, planID: "monthly")
```

Open `checkoutURL` using the platform's browser API. Use RevenueCat's **anonymous** Web Purchase Link and Redemption Links for a no-account product. Do not append this package's local installation ID to the web link in that mode.

## URL callback handling

Register the callback scheme generated by RevenueCat in every consuming app. In SwiftUI, forward incoming URLs to the gateway:

```swift
.onOpenURL { url in
    Task { await gateway.redeem(url: url) }
}
```

`redeem(url:)` returns `false` for unrelated URLs. A successful redemption updates `gateway.status`; the consuming app decides how that status unlocks its own features. Treat the Boolean as URL-recognition information only: the next release will expose a richer result so hosts can distinguish a provider redemption failure from a successful redemption.

`RevenueCatEntitlementGateway` is an `ObservableObject`, so SwiftUI hosts can observe status changes on macOS 13+ and iOS 16+.

## Plans and configuration

Plans are string IDs so each project can choose any combination:

```swift
let plans = [
    EntitlementPlan(id: "lifetime", displayName: "Lifetime"),
    EntitlementPlan(id: "yearly", displayName: "Annual"),
    EntitlementPlan(id: "monthly", displayName: "Monthly"),
]
```

Map those IDs to each RevenueCat offering's package IDs in `WebBillingConfiguration.packageIDsByPlanID`.

For a non-subscription purchase to map to `.lifetime`, include its RevenueCat product ID in `lifetimePlanIDs`. The adapter also treats an active configured entitlement with no expiration date as lifetime. Only put genuinely non-expiring products in that set; marking a renewable product as lifetime would give the host an incorrect local status.

## Offline access

Pass an `EntitlementStatusStoring` implementation to the RevenueCat gateway to persist its last provider-reported status. The built-in `UserDefaultsEntitlementStatusStore` restores it through `status.resolved()` at gateway initialization. It downgrades expired trials to `.free` and expired subscriptions or grace periods to `.expired`, preserving plan identity. The provider remains authoritative when reachable.

## Device access

EntitlementKit intentionally supports unlimited device redemption. RevenueCat
Redemption Links handle the cross-device association flow. If a product later
needs an access-control rule, implement it in that host product rather than
making a shared billing package enforce a policy it cannot verify securely.

## Security and operational notes

- API keys must be public SDK keys only; never embed RevenueCat REST secrets.
- Keep each callback scheme, entitlement ID, Web Purchase Link, and plan mapping project-specific.
- Do not use guessable IDs or email addresses as RevenueCat App User IDs.
- A `UserDefaultsInstallationIdentity` does not survive app deletion. Provide a Keychain-backed `InstallationIdentifying` implementation if that is a requirement.
- Configure and test Redemption Links in RevenueCat sandbox before production.

## Scope boundaries

EntitlementKit is a client-side entitlement library, not an account system, a backend authorization service, a branded paywall, or a device-limit enforcement product. It does not replace a live sandbox billing test, and it is not yet integrated into Uttr. Host apps own their feature gates, branding, product configuration, and any separate access-control policy.

## Development

```bash
swift test
swift package resolve
```

The core target is dependency-free and is covered by Swift Testing. RevenueCat integration should additionally be tested against a sandbox Web Purchase Link and a registered callback scheme in a sample host app.

Every pull request runs the deterministic Web Billing integration-flow suite. It exercises anonymous checkout-link generation, persistent installation identity, cached entitlement restoration, and expiry resolution without a live billing account. A live sandbox smoke test remains a release-readiness check because it needs dashboard configuration and cannot be safely run from ordinary PR CI.

All ongoing changes use topic branches and pull requests into `main`. See [CONTRIBUTING.md](CONTRIBUTING.md) for the review and release workflow.
